## 한 줄 요약

Lesson 5에서 만든 *내 프로젝트 계획*을 꺼내, Lesson 6~8에서 배운 Description과 Discernment를 *실전 루프*로 적용. *사람·AI 어느 쪽도 혼자선 못 만들* 결과를 향해 간다.

## 이 차시는 어떤 차시?

이 차시는 *영상 강의*가 아니라 **실습 활동지**. 지금까지의 모든 *이론*을 *진짜 프로젝트*에 적용한다.

목표:
- Description·Discernment 능력을 *실전*에 옮기기
- *생산적인* Description-Discernment 피드백 루프 만들기
- *사람·AI 각자*가 못 만들 결과를 *함께* 만들기

## Step 1 — 프로젝트 계획 다시 열기

Lesson 5의 *프로젝트 계획서*를 꺼내본다. 빠르게 점검:

- *Delegation 결정*들을 다시 본다 — 사람 강점 / AI 능력 / 협업 영역.
- *그동안 배운 것*에 비추어 *계획을 다듬어도 좋다*.

## Step 2 — Description 접근 준비

AI와 대화 시작. 프로젝트를 설명하고 *작업 시작 전에* 어떻게 Description을 펼칠지 *함께 설계*한다:

### Product Description 점검
- 각 작업에서 AI가 줄 *결과물*은 무엇인지?
- *형식·스타일·길이·디테일* 수준은?

### Process Description 점검
- AI가 *어떻게 접근*해야 하나?
- 특정 *방법·프레임워크·단계*가 있나?

### Performance Description 점검
- AI에게 어떤 *협업 행동*을 원하나?
- *간결 vs 상세 / 도전적 vs 지지적 / 아이디어 vs 분석 중심*?

→ 이 셋을 *AI와 이야기 나누며* 명확히 한다. *기대치 정렬*이 핵심.

## Step 3 — Description-Discernment 루프로 실행

이제 *각 작업*에 대해 다음을 반복:

### A. 명확히 Description
- *결과물*에 구체적 (Product)
- AI 접근·사고를 *안내* (Process)
- *대화 행동*을 명시 (Performance)

### B. *받은 결과*를 Discernment
- 결과물 자체 평가 (Product)
- AI가 거기 도달한 *과정* 평가 (Process)
- AI의 *행동·소통*이 도움 되는지 평가 (Performance)

### C. Discernment 기반으로 *Description 다듬기*
- *통한 것·안 통한 것* 피드백
- 필요하면 Description *조정*
- *원하는 결과*까지 반복

### D. *내 전문성·판단*을 결합
- 내 *고유 관점·창의·분야 지식*을 더한다
- *무엇을 남기고·바꾸고·버릴지* 최종 결정한다
- *최종 결과의 책임*을 진다

이 루프를 *프로젝트의 모든 작업*에 적용해 완성까지.

## Step 4 — 성찰 (잠시 멈추기)

다음 차시 가기 전 3분:

- *어떤 종류의 Description*이 가장 좋은 결과를 낳았나?
- *Description vs Discernment* — 어느 쪽에 더 많은 노력이 들었나? 왜?
- *Lesson 5 계획*과 *실제 실행*은 어떻게 달랐나? 어디서 *조정*했나?

## 비유로 이해하기 🪜

**Lesson 5는 *지도 그리기*, Lesson 9는 *지도 들고 걷기*.**

- 지도 그리기만으론 *실제 길의 흙·바람*을 모른다.
- 걷다 보면 *지도에 안 그려진 샛길*을 발견한다.
- 걷다 보면 *지도에 그린 길이 막힌* 곳도 발견한다.
- 좋은 *여행자*는 — 걸으면서 *지도를 다시 그린다*.

Description-Discernment 루프가 그 일이다. *부탁 → 결과 → 다듬기*가 반복될수록 — *내 지도(생각)*과 *길(AI 협업의 실제)*이 함께 정교해진다.

## 동료에게 권할 때

### 한 줄 정의

> "이번 차시도 *영상이 아니라 실습*이에요. Lesson 5에서 만든 *같은 프로젝트*에 — Description과 Discernment를 *루프*로 적용해보는 시간이에요. 사람도 AI도 혼자선 못 만드는 결과를 만들어봅니다."

### 잘 안 풀릴 때

- *결과가 자꾸 빗나가면* → Product Description부터 점검 (형식·길이·청중이 모호한가?)
- *AI가 헛돌면* → Process Description 강화 (어떻게 접근할지 단계별 가이드)
- *대화가 답답하면* → Performance Description 조정 (어떤 톤을 원하는지)
- *그래도 안 되면* → Delegation 재검토 (이 도구가 이 일에 안 맞을 수도)

### 짝과 함께

- 짝의 *루프 대화 1턴 전후*를 보고 — *어디서 Description이 바뀌었나*, *결과 차이*는 어땠나 토론.
- 짝과 *같은 Step 2 질문*에 답하고 비교하면, *내가 어디에 치우쳤는지* 보인다.
